## 4. 未完成目标（按建议优先级）

### P0：清理旧 GitHub 全范围快照，并完成受限范围的真实验收

现有旧 GitHub 连接可能来自范围选择上线前，`config` 没有 `selected_repository_ids`。它的历史数据可以浏览，但不得继续手动同步，否则会被安全策略拒绝。

执行步骤：

1. 启动新版本 Desktop：`cd apps/desktop && rtk pnpm tauri dev`。
2. 在“连接器”找到旧 GitHub 连接，选择“删除本地数据”。
3. 核对预览的资源、关系、版本、变更、绑定和同步记录数量；点击“确认删除本地快照”。此操作不可恢复。
4. 用新 UI 建立 GitHub 连接：输入名称与 fine-grained Token，选择“验证并加载仓库”，只勾选一个或少量测试仓库。
5. 验收：确认 Overview、Inventory、Connectors 与 Timeline 都能读取快照；确认资源只属于已选仓库；确认未出现 Token 或原始 Provider payload。

### P0：将 Scheduler 接入 Desktop Host 的实际周期执行

`next-infra-runtime` 内已实现 Scheduler、`register` 与 `plan_due`，但当前 Desktop composition 没有注册已配置连接，也没有轮询/消费 `plan_due`。因此当前可依赖的是建连后的首次后台同步和手动同步；**长期运行的定时同步不能标为完成**。

后续实现需要：

1. 对每个已启用连接从 descriptor 取得推荐间隔并注册 Scheduler。
2. 在 Desktop Host 生命周期中启动可取消的定时驱动，只将 due 任务交给已有的有界同步入口。
3. 在睡眠/唤醒时使用现有 catch-up 语义，禁止补跑无限次数。
4. 为排队、并发、显式 Quit、运行中删除连接与 App 重启增加集成测试。

### P1：真实 Provider / SSH 只读 smoke

- [ ] Dokploy、Cloudflare、Supabase managed/self-hosted：每条路径使用最小只读权限，验证账户/项目范围、分页和 partial。
- [ ] 阿里云、腾讯云：验证最小只读凭据、区域分页、限流与部分失败。
- [ ] 任何真实响应均不得写入测试 Fixture、文档、日志或 Git。

### P2：凭据、签名与原生 macOS 生命周期

- [ ] 将 GitHub MVP 的本地 Token 文件迁移到 Keychain，并验证锁屏、自动登录与后台访问失败语义。
- [ ] 提供 Apple Development 或 Developer ID identity 后，执行 codesign、notarization 和已签名 App 的生命周期 smoke。
- [ ] 验证托盘、close→hide、show、显式 Quit、单实例、登录启动与 MCP 可信自动拉起。

### P2：扩展连接录入 UI

当前可由终端真实录入并同步的 UI 路径仅覆盖 GitHub。SSH/Dokploy/Cloudflare/Supabase/云厂商虽已有 Connector 实现或 descriptor，但没有已验收的通用“新建连接 / Provider Secret”用户流程。后续应按每种凭据模型单独设计，而不是暴露通用 Secret 文本框。
