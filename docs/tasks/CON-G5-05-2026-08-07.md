## 问题

添加 GitHub 连接时两步均失败，Token 正确：

1. "验证并加载仓库" → `无法验证 Token 或加载 GitHub 仓库`（错误码被 UI 吞掉）
2. 选择仓库后创建 → `无法创建 GitHub 连接（github_validation_failed）`

## 根因 1：发现路径分页预算 bug

`composition::github_discover_repositories` 用 `GitHubFetchBudget::new(1, 1)`，但 `fetch_pages_with_budget` 在循环头部检查预算：`/user/repos?per_page=100` 返回 `Link: rel="next"`（可访问仓库 >100 时），第 2 轮循环直接返回 `Err(PartialPagination)`，被当作硬错误。**>100 个可访问仓库时发现仓库必失败。**

修复（`composition/mod.rs`）：`Err(PartialPagination)` 且 `failure.is_partial()`（有已完成页）视为成功，使用已取页（恰好是"最多 100 个仓库"的承诺）；其他错误照常失败。

## 根因 2：config 契约自相矛盾

| 检查点 | 要求 | 矛盾 |
| --- | --- | --- |
| `validate_connection_input`（connector.rs） | config **必须为空对象** `{}` | 与范围选择策略相反 |
| `selected_repository_ids()`（connector.rs，sync 时） | config **必须含非空** `selected_repository_ids` | — |

composition 建连写入 `{"selected_repository_ids": [...]}` → validate 必失败 → `github_validation_failed`。同时导致 **4 个预存测试失败**（fixture 用空 config，validate 通过但 sync 被 guard 拒绝）；`cargo test` 在 lib 失败后不运行后续集成 target，`connector_pipeline` 等集成测试因此从未执行。

修复（`crates/next-infra-connector-github`）：

- `validate_connection_input`：空对象要求 → 必须含非空 `selected_repository_ids`（与 sync 守卫一致）。
- fixture 同步更新（同一根因）：`connector.rs` 测试 helper `sync_request()`、`tests/connector_pipeline.rs`（`connection()` 与 `request()`）、`tests/repository_contract.rs`、`tests/actions_contract.rs`：config `{}` → `{"selected_repository_ids": ["10"]}`（fixture 仓库 id=10）。

## 伴随改进

- `ConnectorsPage.tsx`：发现/建连 catch 用 `desktopErrorCode(error)` 透出真实错误码（`github_rate_limited` / `github_unreachable` / `github_auth_failed` / `desktop_transport_failed`…），不再吞错误。
