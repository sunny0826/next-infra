# RHM-G4-02B Local RPC Session 与 Query Adapter 验收记录

**日期：** 2026-08-04  
**状态：** `REVIEW`  
**范围：** Unix stream handshake、peer UID、typed Query dispatch、per-session in-flight admission、client API；不包含 MCP STDIO、Host 自动拉起或 Desktop composition。

## 交付结果

- `RpcServer` 在读取任何 Query 前验证 peer UID，并要求 `ClientHello`；非握手 frame 返回无 request ID 的 typed `HandshakeResponse::Rejected`。
- Host 根据双方 minor 区间设置 `selected_protocol_minor`，复用冻结的双向版本/capability negotiation。
- rejected handshake 写回结构化 `protocol_mismatch` / `capability_mismatch` 后结束 session。
- accepted session 只反序列化冻结的 `RequestEnvelope`；请求 capability 必须属于 negotiated Host capability set。
- `QueryServiceHandler` 将七个 `QueryRequest` 一一映射到共享 `QueryService`，不复制 SQL、bounds、cursor、Freshness 或 DTO 语义。
- Query errors 清洗并映射为稳定 `query_failed`；response 回显 request ID。
- 每个 session 最多 8 个 active worker；第九个请求立即返回 `too_many_requests`，不进入 queue，也不创建第九个 worker。
- response writer 通过单 mutex 串行；worker 完成顺序可以不同，但每个 response 由 request ID 关联。
- in-flight permit 使用 Drop 归还，即使 handler panic 也不会永久占用 admission slot。
- `RpcClient` 支持安全路径连接、server peer UID 验证、handshake 自校验和顺序 Query。
- `serve_once` 使用真实 `SecureUnixListener` accept；Socket pair 仅用于精确状态机/并发测试。

## Wire 验收

自动化测试覆盖：

1. 真实 owner-only filesystem UDS connect → handshake → Query。
2. 七个 QueryService route 全部 round-trip。
3. Query-before-handshake 返回 typed `invalid_frame` rejection。
4. major mismatch 返回 typed `protocol_mismatch` rejection。
5. 八个 handler 被阻塞时，第九个请求立即返回 `too_many_requests`。
6. request ID 精确回显，八个并发成功 response 均可关联。

Session suite 连续运行 20 次；早期四项核心 session suite 另连续运行 50 次，未出现 admission/response ordering flake。
