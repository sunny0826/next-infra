# RHM-G4-02A Secure Unix Transport Foundation 验收记录

**日期：** 2026-08-04  
**状态：** `REVIEW`  
**范围：** owner-only run directory、lock/socket lifecycle、bounded stream framing、peer UID primitive 与 client/server path validation；不包含 handshake session、Query dispatch 或 MCP。

## 交付结果

- `TransportPaths` 固定 `run/next-infra-v1.sock` 与 `run/next-infra-v1.lock`，新建 `run/` 时以 `0700` mode 创建并再次验证 owner/type/mode。
- lock 使用 `O_NOFOLLOW | O_CLOEXEC`、`0600` regular file 和 non-blocking exclusive `flock`；live owner 存在时第二 server 不清理 socket。
- stale socket 只有在持有 lock、owner/type/mode/identity 正确且 connect 返回 refused/not-found 后才清理。
- listener bind 后 socket mode 为 `0600`；accept 前后验证 path identity，Drop 只清理本实例仍拥有的 inode/device。
- client connect 前后验证 socket owner/type/mode/identity；peer credential 作为随后必须执行的独立验证步骤。
- macOS 使用 `getpeereid`；测试接口可注入 peer UID lookup 验证 mismatch 分支。
- stream reader 先读取 4-byte header，确认 `1 MiB` 上限后才分配 body；覆盖 fragmented read、EOF、zero/oversized body 和 invalid JSON。
- transport 不引入 Tokio、TCP、HTTP、Tauri、Store、Keychain、Connector 或 Provider 依赖。

## 主线 Review 修正

- 将 `run/` 从“创建后 chmod”收紧为以 `0700` mode 创建，缩小首次创建窗口。
- 确认并保留 worker 提供的 `connect_unix` 前后 owner/type/mode/identity 校验，删除重复 client connect 实现。
- transport security suite 连续运行 20 次，未出现 socket identity/permission flake。
