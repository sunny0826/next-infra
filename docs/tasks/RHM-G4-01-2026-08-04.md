# RHM-G4-01 Local RPC v1 Contract 验收记录

**日期：** 2026-08-04  
**状态：** `REVIEW`  
**范围：** Host/Bridge typed protocol、framing、握手协商、资源上限和 golden contract；不包含 Unix Socket、MCP STDIO、Host 自动拉起或 Agent 配置。

## 交付结果

- Local RPC v1 使用 4-byte unsigned big-endian body length + UTF-8 JSON，body 上限固定为 `1 MiB`。
- 编码器使用受限 writer，在形成超限 body 前停止；解码器先检查 header/length，再复制已验证的 body。
- 初始协议固定为 `1.0`，minor 支持窗口最多覆盖当前与前一 minor，并选择双方区间最高交集。
- Client/Host required capability 双向验证；兼容但 release ID 不同时返回 `upgrade_recommended=true`。
- 握手首个 response 使用无 request ID 的 `HandshakeResponse::{Accepted, Rejected}`；失败不伪造 Query request ID。
- capability 集合精确限制为七个只读 Query，未知项和重复项拒绝反序列化。
- request/response 使用封闭 serde enum，不存在任意 method、params、SQL、Secret、Credential、Connector、refresh 或配置修改 variant。
- request ID 按 UTF-8 bytes 限制为 128；反序列化路径与构造器路径执行相同校验。
- session in-flight 上限冻结为 8；实际 admission enforcement 留给 `RHM-G4-02`。
- wire 错误码冻结为 `host_unavailable`、`protocol_mismatch`、`capability_mismatch`、`invalid_frame`、`frame_too_large`、`invalid_request_id`、`too_many_requests`、`query_failed`。
- Client/Host hello golden fixture、精确 framing bytes、七个 request/response round-trip、错误码、兼容窗口和超限行为均有自动化证据。

## Review 修正

独立主线 Review 修正了首版实现中的三处契约漂移：

1. 将错误码从非冻结拼写 `oversized_frame` 改为 `frame_too_large`。
2. 将 minor range 明确限制为 `protocol_minor - minimum_supported_minor <= 1`。
3. 为 request/response envelope 增加 serde `try_from` 校验，防止直接 wire 反序列化绕过 request ID/caller 校验。
