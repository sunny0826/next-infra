## Live smoke 暴露并修复的连接器缺陷（9 项）

1. **SecretId 硬编码 `"fixture-secret-id"`** → 从 `config.secret_id` 读取。
2. **单 endpoint `cvm.tencentcloudapi.com`** → 按产品分派：cvm / vpc（含 subnet、security_group、addresses）/ clb / dnspod。
3. **Region 前缀 `tencent:` 未剥离** → strip 后使用。
4. **响应信封假设扁平 `Items`** → 真实是 `{"Response": {TotalCount, <Xxx>Set/List, ...}}` → 通用提取（Response 内首个数组 + 扁平兜底）。
5. **ID 字段名不统一**（InstanceId/VpcId/SubnetId/SecurityGroupId/LoadBalancerId/RecordId/AddressId + 数字型 RecordId）→ 自定义 Deserialize（优先级列表，支持数字转字符串）。
6. **DNS 记录需 `Domain`** → 两步走：`DescribeDomainList` → 逐域名 `DescribeRecordList`（上限 20）。
7. **TC3 公共头缺失**：`X-TC-Version`/`X-TC-Region`/`X-TC-Timestamp` → 补齐（timestamp 由 SignedRequest 携带）。
8. **payload 含 Action/Version/Region 被拒（UnknownParameter）** → 移出 payload（只走 X-TC-* 头）；TC3 签名仅覆盖 content-type;host + payload 哈希（测试断言同步修正）。
9. **VPC 系 `Limit/Offset` 需字符串、CVM/CLB 需 int64** → 按 service 分派类型。

**known-gap（未解决）**：DNSPod `DescribeDomainList` 的 `Limit` 参数无论字符串还是数字均报 `InvalidParameter: input type should be int64`（官方文档声明 Limit 为 Integer，示例为数字；疑似网关解析怪癖）。已按"模块级失败 → Partial（仅认证类硬错误）"语义优雅降级，不阻塞其他模块。
