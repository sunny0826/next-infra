# RHM-G4-04B Bridge Auto-launch 状态机验收记录

**日期：** 2026-08-04  
**状态：** `REVIEW / LIVE-SIGNATURE-SMOKE-BLOCKED-ENVIRONMENT`  
**范围：** Bridge 侧可信自动拉起、Local RPC 握手 deadline、production codesign verifier 与固定 launcher；尚未接入 Bridge entrypoint 或 Desktop 二次授权。

## 交付结果

- `ensure_host` 首先尝试现有 owner-only UDS；成功时不读取 integration record、`user_quit` 或签名状态，也不调用 launcher。
- 现有 Host 连接与拉起后的握手都使用真实 Unix socket 读写 timeout；withholding peer 不能无限阻塞 Bridge。
- 自动拉起顺序固定为：检查 `user_quit` → 验证 IntegrationRecord → 要求 `allow_mcp_auto_launch=true` → 验证 App/Bridge → 再次检查 marker 和 artifact identity → 单次固定 launcher → 最多 10 秒 monotonic wait → 真实 Local RPC handshake。
- caller 提供的超时即使大于 10 秒也会被强制截断；每次 post-launch handshake 只获得当前 deadline 的剩余时间，deadline 到达后的成功连接也不会被接受。
- 等待期间或成功握手同时出现 `user_quit` 时立即返回 `host_unavailable`；Bridge 不创建、删除或改写 marker。
- production launcher 使用原子 latch，同一 launcher 实例最多尝试一次；唯一 argv 为 `/usr/bin/open -g <validated app> --args --background --launch-source=mcp`，不经 shell 或 PATH。
- production verifier 使用 `/usr/bin/codesign` 精确验证 App 与当前 Bridge 的 recorded requirement、Team、App Identifier 和 designated requirement。
- App/Bridge 在验签前后必须保持相同 device/inode；launcher 前再次校验 identity，并再次验证 App bundle 签名，降低 pathname 与 bundle 内容替换窗口。
- `codesign` 的 Identifier、TeamIdentifier 和 designated requirement 必须恰好出现一次且非空；重复、冲突、缺失或非 UTF-8 输出全部 fail closed。
- 默认 Local RPC API 保留 10 秒握手上限；成功握手后会清除 handshake 专用 socket timeout，避免把临近 deadline 误带入后续只读 Query。

## 自动化证据

- Bridge availability tests 覆盖 fast path、合法/损坏 marker、auto-launch disabled、签名失败、artifact replacement、单次 launcher、10 秒硬上限、等待期 marker、固定 argv 和严格 codesign 输出解析。
- Local RPC 使用真实 socket pair 验证 withholding peer 在 deadline 内失败。
- MCP client 使用真实 owner-only UDS 验证 bounded run-directory connect。
- 所有测试使用临时目录、fake verifier/launcher 或 withholding fixture；没有调用真实 `/usr/bin/open`，也没有把 fake/ad-hoc signature 记为 live pass。
