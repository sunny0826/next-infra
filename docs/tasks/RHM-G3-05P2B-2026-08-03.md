# RHM-G3-05P2B Committed QuerySource 验收记录

**日期：** 2026-08-03  
**状态：** `REVIEW`  
**范围：** Runtime-owned CommittedQuerySource、immutable QueryContext、Store projection → QDTO 映射与真实 SharedStore 查询；不包含 Tauri Composition、Host effects、Provider 或外部写操作。

## 1. 交付结果

- Runtime 新增 `CommittedQuerySource`，与 `SqliteRuntimeBackend` 共享同一个 `SharedStore`，不 reopen SQLite。
- `QueryContextSnapshot` 固定一次查询使用的 `evaluated_at`、schedule 与单调 revision；cloneable refresh handle 只发布完整新快照。
- Snapshot metadata 组合 committed Store revision、catalog fingerprint、evaluated timestamp 与 query-context revision；`generated_at` 输出 UTC RFC 3339 毫秒格式。
- 八个 QuerySource surface 全部映射到公开 QDTO：resource search/detail、connection snapshot、topology、health summary、recent changes、sync status、connector coverage。
- Freshness 严格按每 Connection interval 计算：`fresh <= 1×`、`stale <= 3×`、其余 `expired`；缺少 schedule 时安全失败，不猜默认值。
- Provider/Configured/Inferred relation evidence 使用 Store 同事务返回的权威 provenance；缺少必需 metadata 时安全失败，不伪造。
- Connector Coverage 来自冻结 catalog snapshot；Connection DTO 结构上排除 config 与 SecretRef。
- Resource Detail 遇 Store relation/change truncation 时返回安全 source failure，不静默返回不完整证据。
- SyncRun error 对外 message 按 error code 生成固定安全文案，原始 provider message、token、路径或 payload 不进入 QDTO。

## 2. Bounded Topology

- traversal 以 focus Resource 为 depth 0，逐层读取有界 relation frontier。
- 严格遵守 QueryService 提供的 depth/node/edge 限制，不执行 load-all。
- 同 endpoints 的多条 relation/evidence 不合并、不丢失。
- 只有因 node/edge 上限无法纳入的邻居进入 frontier，并设置 `truncated`。
- Review 修正了 depth 1 的 off-by-one：一跳邻居现在进入 nodes，返回的每条 edge 两端都存在于 nodes，不再产生悬空边。

## 3. 黑盒证据

真实临时 SQLite + 同一 SharedStore integration tests 覆盖：

1. Writer commit 后，QueryService 读取 Resource、Relation、Change、SyncRun 与 Connection。
2. search/detail/changes/sync/coverage/connections 返回相同 committed snapshot version。
3. injected QueryContext 驱动 fresh → stale → expired，Resource Health 不被改写。
4. Connector Coverage 与 Provider relation provenance 映射正确。
5. 默认一跳 topology 保持 node/edge 一致性，并在 node cap 下返回 frontier/truncated。
6. 401 条 detail relations 触发安全 source error，而不是返回前 400 条伪装成完整结果。
7. Connection config/SecretRef 与 SyncRun 原始 provider error 哨兵均不会出现在序列化 QDTO。
