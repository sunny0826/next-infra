# CON-G9-S5 Supabase self-hosted live smoke 验收记录

**日期：** 2026-08-07
**状态：** `PARTIAL`（连接器数据面已重新设计并实现；仅剩实例网关 TLS 指纹过滤外部阻塞）
**关联：** [`LIVE-SMOKE-PLAN-2026-08-07.md`](./LIVE-SMOKE-PLAN-2026-08-07.md) CON-G9-S5

## 验收事实（实例：supabase/studio 2025.04 版本自托管栈）

| 项 | 结果 |
| --- | --- |
| Key 有效性 | ✅ 有效（`apikey` 头经 curl 通过网关到达 PostgREST，返回 404=表不存在而非 401；JWT 结构 HS256/iss=supabase/role=service_role/未过期） |
| 传输层 | ⚠️ **实例网关对 reqwest/rustls 客户端返回 401**；curl（OpenSSL）在完全相同的 URL/头/方法/代理/HTTP 版本配置下返回 404。差异定位为 TLS 客户端指纹（JA3）过滤，属实例侧 WAF/CDN 行为 |
| 连接器数据面 | ⚠️ **连接器假定的 3 个端点 `/rest/v1/projects`、`/rest/v1/postgres_metadata`、`/rest/v1/runtime_info` 在标准自托管实例上不存在**（PostgREST 表缺失，404）——设计面与真实实例不符 |

## 排查过程与修复

1. 旧 service key 401 → 换服务器 `.env` 的 `SUPABASE_SERVICE_KEY`（180 字符 JWT）→ 仍 401。
2. 解码 JWT：结构完全标准，但**头部无 `kid`**——推测 Kong `key_claim_name: kid` 拒绝 → 用 curl 变体验证：`apikey` 单独发 = **404**（PostgREST 接受了 key），带 `Authorization: Bearer` = 401（Kong jwt 插件）。
3. **修复（harness）**：self-hosted transport 只发 `apikey` 头、去掉 `Authorization: Bearer`（与真实实例行为一致，已保留）。
4. 修复后 harness 仍 401：curl 对照（代理/直连/HTTP1.1/HTTP2/Content-Type/UA 全组合均 404）→ 唯一差异为 TLS 客户端指纹。

## 结论与建议

- **认证头修复**（apikey-only）为真实修复，保留。
- **实例网关指纹过滤**：需用户侧处理（WAF 放行规则）或改用原生 TLS 后端（工作区级 reqwest 改 `native-tls`，改动面大，待用户决策）。
- **连接器数据面缺口**：`service_api`(projects)/`postgres_metadata`/`runtime` 三个模块基于假设的 API 形状，标准自托管实例（PostgREST）无这些表——需产品决策：自托管实例应收集什么（建议：PostgREST OpenAPI 表清单 `/rest/v1/`，或将该连接器标记为 known-gap/unsupported，参照 DEC-G8-01 Dokploy Database 的处理方式）。
- 任务保持 `BLOCKED-EXTERNAL`，不冒充通过。

## 重新设计（2026-08-07）

**决策：** 采用 PostgREST OpenAPI 表清单方案（`GET /rest/v1/`）。原 3 个假设端点（`/rest/v1/projects`、`/rest/v1/postgres_metadata`、`/rest/v1/runtime_info`）删除。

### 新的数据面

| 资源种类 | 来源 | 属性 |
|---|---|---|
| `supabase.self_hosted.table` | OpenAPI `paths` 键，每条路径一个资源 | `table`（表名）、`schema`（如有）、`auth_role`（如有）、`description`（如有） |

**采集方式：** `GET {url}/rest/v1/` → 解析 OpenAPI JSON → `paths` 对象键 → 过滤 admin 路由（`/_*`、`/`）→ 每条剩余路径生成一个 `table` 资源。

**路径→表名解析启发式：**
- `"/users"` → table=`users`，schema=`null`
- `"/public.profiles"` → table=`profiles`，schema=`public`
- `"/_health"`、`"/"` → 跳过

**边界：** `MAX_TABLES = 500`；超限 → `SyncOutcome::Partial` + `CoverageGapReason::PaginationIncomplete` + warning。

**输出：** 无 credentials、无 connection strings、无 data rows；仅表名（来自 spec path 键）。无 relations。

**Descriptor 变更：**
- 删除了 `supabase.self_hosted.{service,database,runtime}` 三个 kinds
- 替换为单一 `supabase.self_hosted.table` kind，coverage module `supabase.self_hosted.tables`，level `Partial`（reason: "PostgREST-exposed table inventory; user-defined schema varies by instance"）
- `known_gaps` 新增：TLS fingerprint（reqwest 401）、无 row data、无 Studio API
- `sensitive_field_policy`：明确排除 credentials、connection strings、data rows

**SourceKind 变更：**
- 删除了 `ServiceApi`、`PostgresMetadata`、`FixedSshProbe` 三个 variant
- 替换为单一 `OpenApi` variant（对应 `SelfHostedTransport::read_openapi` trait method）

**Transport trait 变更：**
- `async fn read(source: SourceKind)` → `async fn read_openapi()`（单端点，无需 variant 参数）

**Auth：** `apikey` header only（`Authorization: Bearer` 触发 Kong JWT 401）。harness transport 已同步（Bearer prefix 移除）。

**Config：** 保持 `{ url, service_key }` 形状（`url` = instance base，connector 追加 `/rest/v1/`）。
