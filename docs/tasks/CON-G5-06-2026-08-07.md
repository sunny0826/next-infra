## 关于"部分覆盖 / 降级"的判定

**结论：非特定模块问题——GitHub 同步运行天生就是 Partial，健康度恒为降级（有界纵切设计）。**

代码链：`Collector::finish`（connector.rs:590）在 `primary_failure` 为 `None` 时兜底为 `bounded_failure()`（PartialPagination "GitHub connector provides a bounded current view"），因此 `SyncOutcome::Partial` 是 GitHub 有界纵切的固有输出；`composition::sync_github` 将 Partial 一律映射为 `ConnectorHealth::Degraded`。与所选仓库大小、具体模块无关。

"最近错误：无"与之一致：模块级截断（runs>100/仓库、workflows>200、jobs 上限、分页/请求预算）产生的是 `ObservationWarning`（如 "GitHub module github.actions.runs reached its bounded view"），运行 errors 仅在硬失败（`engine.fail`）时记录；当前 UI 未透出 warnings。

若期望小范围连接显示 Healthy（将"有界纵切完整"映射为 Healthy）或在 UI 展示 warnings，属产品决策，不属于 P0-1 范围。
