## 1. 交付

- 新增 generic `GitHubConnector<T, C>` 并实现共享 `ReadConnector`。
- `validate` 仅请求 `/user`，验证空配置、schema、临时 token 和 JSON object response。
- Full 固定采集 Repository → Environment → Deployment → Workflow → Run → Job。
- Targeted 仅接受 Repository locator，并精确使用 Full 产生的 process-local route cache。
- ETag/page cache 仅存在进程内；有完整 cache 才发送 ETag，304 复用 cached pages，无 cache 304 fatal。
- client 支持显式 `GitHubFetchBudget`，每次 fetch 只能收紧 20 pages/200 requests 硬上限；collector 在发请求前传入剩余全局预算。
- 首版顺序执行，并发 1，不超过 Descriptor guidance 2。

## 2. Coverage 与删除语义

Run/Job 是 bounded current view，Deployment Status unsupported；聚合 `ObservationBatch` 始终使用 `SyncCoverage::Partial`，不会贡献 missing evidence。

Descriptor 已更新为真实 module coverage：Repository、Environment、Workflow 及稳定 contains relations 为 Supported；Deployment、Run、Job 及其有界历史 relations 为有原因的 Partial。已移除 mapper/collector pending 过时状态。

## 3. 自动化证据

GitHub crate 共 42 tests，纵切重点覆盖：

- 一轮 Full 只调用六类 allowlisted endpoints，产生 6 resources/5 relations。
- 第二轮六个 304 全部使用 ETag 并复用 cached pages；summary 记录六个 3xx 请求。
- 无 cache 304、Repository 401 为 fatal。
- Targeted Full cache hit 后只按 exact route 访问 `/repos/{owner}/{repo}`；cache miss 在网络调用前失败。
- Environment 403 仅 module partial，其他五类资源继续存活；body sentinel 不进入 batch/debug。
- validation 使用只读 `/user`，未知 response 字段不保存。
- client page/request budget、same-origin Link、cycle、Retry-After/reset/body size 继续由 G5-01 tests 覆盖。

真实临时 SQLite/SyncEngine test：

1. 第一轮 GitHub partial 写入六类资源；
2. 第二轮仅 Repository 成功，五个 child module permission partial；
3. commit 后六类资源全部仍为 `Lifecycle::Active`，第二轮 SyncRun 为 `Partial`。

这证明 GitHub 的 bounded/permission partial 不会触发 Tombstone。

## 4. 安全边界

- Connector 不依赖 Store、Runtime、Query、Tauri、MCP 或 Keychain。
- token 仍只以调用方临时 `SecretValue` 进入 sensitive header，不进入 cache。
- page/route cache 不序列化、不落盘，Debug 不输出 owner/name/body/token。
- 不调用 logs、artifacts、statuses、Secrets、Variables 或 write endpoints。
- 未使用真实 GitHub token、未保存 live payload。
